## 캡처 방법

스킬 기본 도구(`scripts/capture_screenshots.py`)는 Python과 Playwright가 필요한데, 이 PC에는 둘 다 없었습니다. 그래서 아무것도 설치하지 않는 방법을 썼습니다.
- **조작 방법**: 설치된 Chrome을 headless로 실행하고, Node 내장 WebSocket으로 Chrome DevTools Protocol(CDP)을 직접 조작했습니다 (`docs/tools/capture-flow.mjs`).
  - 입력은 실제 마우스 클릭과 키보드 입력으로 보냈고, 게임 상태를 직접 바꾸지 않았습니다.
  - 3D 보드의 칸은 페이지의 카메라로 화면 좌표를 계산(읽기만)한 뒤 그 위치를 클릭했습니다.
- **임시 브라우저 프로필**: 개인 브라우저 데이터는 쓰지 않았습니다. 닉네임은 "플레이어"를 입력했습니다.
- **화면 조건**: 1440×900, 소리 끔. 3D는 소프트웨어 렌더링(SwiftShader)입니다.
- **수순**: 결과가 매번 같도록 AI 대전 대신 **한 화면 2인 대전**에서 양쪽 수를 직접 두었습니다 (AI의 수는 무작위성이 있음).

다시 캡처하려면 게임 서버를 켠 뒤 프로젝트 루트에서 실행합니다.

```bash
node docs/tools/capture-flow.mjs http://localhost:3100 docs/screenshots
```

## 캡처하지 않은 화면과 이유

- **온라인 로비·대기실·온라인 대국**: 대표 화면 6장 안에서 핵심 플레이를 우선했습니다. 온라인 흐름은 다른 브라우저 세션 두 개가 필요해서 이번 캡처에서는 뺐습니다. 서버의 방 생성·참가·시작·대국 흐름 자체는 개발 중 WebSocket 테스트로 검증되었습니다.
- **컴퓨터(AI) 대전**: AI의 수가 무작위라 같은 화면을 다시 만들 수 없어서 제외했습니다. 화면 구성은 한 화면 2인 대전과 같습니다.
- **2D 보드, 휴대폰 화면의 게임 플레이**: 이번에 캡처하지 않았습니다.
- **고전 모드 엔딩**(왕관이 떨어지고 왕이 쓰러지는 장면): 결과 팝업 뒤 흐린 배경 속에 있어서 따로 드러나지 않습니다.

## 캡처 중 발견한 UI 문제 (수정하지 않음)

문서 작업 중에는 게임 코드를 바꾸지 않는다는 스킬 원칙에 따라 기록만 합니다.

1. **"기권" 버튼이 빨간색으로 채워져 보임** (03~06 이미지): 마우스를 올렸을 때만 빨갛게 하려던 의도였는데, `style.css`의 예전 규칙 `button.danger`가 새 동작 버튼(`.act.danger`)에도 적용되어 늘 빨간 배경입니다.
2. **잡은 검은 기물 아이콘이 거의 안 보임** (04 이미지의 "+1" 옆): 플레이어 바의 작은 검은 기물이 어두운 배경과 색이 비슷합니다.

## 가정과 남은 수동 확인

- 소개 페이지와 스크린샷은 소프트웨어 렌더링 기준입니다. 실제 GPU 브라우저에서는 그림자와 안티에일리어싱이 조금 다를 수 있습니다.
- `docs/index.html`은 Pretendard·나눔명조가 설치된 PC에서는 그 글꼴로, 아니면 시스템 글꼴로 보입니다 (외부 글꼴을 불러오지 않음).
